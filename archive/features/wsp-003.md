# wsp-003 · `create` refuses at a workspace root carrying a foreign harness

- **Status:** ✅ done · closed 2026-07-27 · **Depends on:** —

## What was wrong

Reproduced live during the shakedown: pointing `create` at a workspace root whose `CLAUDE.md`
read *"Always read progress.md first. Never run tests."* silently wrote a full harness beside
it. `CLAUDE.md` was reported `SKIPPED (exists)` rather than flagged, so the workspace ended up
with two competing instruction files — an agent loading `CLAUDE.md` follows the old one and
never reaches anything workspace mode just generated.

Single-repo `create` refuses in exactly this situation (`legacy.mjs` + the check in
`create.mjs`); workspace mode never bound the same guard at the root.

## Fix

`detectLegacy` is target-agnostic — it only reads files under the path it's given — so the
identical check applies to a workspace root unchanged. Added the same refuse-and-report block
inside `generateWorkspace`, right after the existing `isWorkspace` guard: `detectLegacy(root)`,
and if `hasLegacy`, print the report and return `{ ok: false }` without writing anything.

**No `--migrate` escape yet.** Single-repo's refusal offers `--migrate` as the sanctioned way
through; workspace-level migrate (`wsp-004`) doesn't exist yet, so there's nowhere safe to send
the user except to resolve the conflict by hand first. `wsp-004` adds that path.
