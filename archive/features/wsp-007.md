# wsp-007 · Root `verify.sh` stops clobbering user edits on re-run

- **Status:** ✅ done · closed 2026-07-27 · **Depends on:** —

## What was wrong

`writeVerify` wrote the root orchestrator with `{ ...opts, force: true }` — hardcoded,
regardless of the caller's own `--force` flag. Any hand-edit to the root `verify.sh` (an extra
check, a comment, a notification step) was silently discarded on the very next `create` run,
violating `SKILL.md`'s "never overwrite blindly" invariant, which every other generated file
already honours.

The `force: true` wasn't an oversight, though — it was deliberate, to make `--add-member`
(`ws-010`) update the orchestrator's `AREAS`/`PATHS` arrays without a stale hand-edit hiding a
new member from verification. Simply removing `force: true` would have fixed the clobber but
silently broken `ws-010`.

## Fix

`generateWorkspace` now captures whether `--add-member` actually added a member this run
(`memberAdded`, from `addMember`'s own return value) and threads it into `writeVerify`. The
root `verify.sh` write becomes `force: writeOpts.force || memberAdded` — forced only when the
caller explicitly asked (`--force`), or when this run genuinely changed membership. A plain
re-run with neither now respects the "never overwrite blindly" rule like every other file.
