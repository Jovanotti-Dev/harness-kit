# wsp-006 · Evidence-link check accepts URLs instead of failing them as dead paths

- **Status:** ✅ done · closed 2026-07-27 · **Depends on:** —

## What was wrong

Found on the real Twyne workspace during the shakedown: `FEATURES.md` cited a merged PR —
`[PR #1](https://github.com/Jovanotti-Dev/twyne-ios/pull/1)` — arguably the strongest evidence a
row can carry, and the "Evidence links resolve" check reported it as a dead link. The check did
`existsSync(path.join(target, rel))` on whatever it extracted from the markdown link, with no
guard for the extracted value being a URL rather than a relative path — a URL can never resolve
as a filesystem path relative to the repo root, so it always failed.

## Fix

One guard added in `checks.mjs`: `isUrl = (s) => /^https?:\/\/i.test(s)`, filtered out before
the `existsSync` check runs. A URL is accepted on sight, not fetched — `audit.mjs` is
documented as static-only (no project commands, no network), so actually verifying a URL
resolves is a check this tool deliberately doesn't perform, not a gap being papered over.
