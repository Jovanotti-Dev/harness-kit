# wsp-009 · Interactive adopt: pick members, import each with history, stop before the destructive step

- **Status:** ✅ done · closed 2026-07-28 · **Depends on:** `wsp-005`

## What was missing

`wsp-005` refuses to generate into a polyrepo, correctly — but a user who *asked* to build a
monorepo, having explicitly named the projects in `WORKSPACE.md`, had no sanctioned tool to do
it with. `references/polyrepo-convert.md` documented the manual `git subtree` procedure; nothing
automated it.

## The boundary this operates inside

From the constitution's destructive-vs-additive amendment: `git subtree add` **reads** a
member's `.git` and writes only to the root — additive, so a tool may run it. Deleting the
member's `.git` afterward is destructive and irreversible, so a tool may not, ever, under any
flag.

## Fix

`--adopt`, wired into `generateWorkspace`, operating on exactly `wsp-005`'s candidates
(`detectMemberGitRoots`, reused rather than reimplemented). For each member with its own `.git`:

1. Move the original to `.adopt-staging/<area>/` — never deleted, one `mv` restores it.
2. `git subtree add --prefix <area> <staged> <branch>` (branch auto-detected). `--no-history`
   copies the working tree instead, staging the original the same way, and names how many
   commits it's choosing to drop.
3. Stop at the first failure — no further members touched, the failed one's original exactly
   where the error says, with the recovery command printed.
4. On full success, print that originals are in `.adopt-staging/` for review and removal —
   **the tool's own doing stops there.**

**New library:** `scripts/lib/adopt.mjs` (`detectAdoptable`, `adoptMembers`). **New probe
helper:** `runGit` in `probe.mjs` — unlike the read-only, error-swallowing `runProbe`, this
never catches: a mutating git command's failure must surface, not vanish into a silent `null`.

## Two real bugs found building this, both from actually running it

1. **`.adopt-staging/` doesn't exist on the first adoption of a run** — `fs.rename` doesn't
   create parent directories. Fixed with `mkdir(recursive: true)` first.
2. **`git subtree add` requires a clean working tree**, and `refreshStacks` (persisting
   detected stacks to `WORKSPACE.md`) ran *before* the adopt step, dirtying a tracked
   `WORKSPACE.md` moments before subtree needed it clean — failing on a real machine, not a
   contrived one. Fixed by reordering: `generateWorkspace` now detects members read-only
   first, runs `--adopt` against that (untouched) filesystem state, and only persists stacks
   (`refreshStacks`) afterward. Neither bug showed up in isolated unit tests — both surfaced
   only by running the actual CLI end-to-end, which is why every test below drives `create.mjs`
   as a real subprocess rather than calling library functions directly.

## The "never auto-commit" exception

`git subtree add` cannot merge history without producing a commit — no way around it. Scoped
narrowly in a new `CONSTITUTION.md` decision (2026-07-27): applies only to the merge commit
itself, never the harness files (`AGENTS.md` etc. stay uncommitted exactly as always); fires
only under explicit `--adopt`; is announced before it runs, not discovered after in `git log`.
A test asserts the announcement text is actually printed, not just documented.
