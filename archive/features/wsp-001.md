# wsp-001 · Workspace generates `state/` + `archive/` at the root

- **Status:** ✅ done · closed 2026-07-27 · **Depends on:** —

## Done when

A generated workspace scores 100 on its own audit — the guard that would have caught this
defect, and the reason the existing placeholder-free assertion did not.

## What was wrong

`workspace-generate.mjs` never wrote `state/<name>.md` or `archive/`, though the root
`AGENTS.md` it generates tells the agent at startup to read its own state file, and
`CONSTITUTION.md` mandates the same path. Every workspace shipped scoring 97/100 on its own
audit, with a startup step pointing at a file that was never created.

Reproduced on the shakedown's minimal fixture:

```
harness-kit audit — wsp001
97/100  Excellent
  Files & wiring  7/8  (88%)
    FAIL  At least one state file
```

## Fix

Two new functions in `workspace-generate.mjs`, wired into `generateWorkspace` alongside the
existing root-doc/constitution/breadcrumb/verify writers:

- `writeState` — renders `state.md.template` (the same template single-repo `create` uses) with
  `GIT_USER` from `gitUser(root)`, and writes it to `state/<slugifyUser(user)>.md` at the root.
  Goes through the normal `writeOut`, so a re-run does not clobber an existing state file.
- `writeArchive` — writes `archive/features/.gitkeep` and `archive/sessions/.gitkeep`, exactly
  one `archive/` at the root, matching `rotation.md`'s workspace-mode note.

The hoist path was checked separately: `hoistMembers` already archives a member's old
`state/` dir to `archive/legacy/<area>/state` before the root files are generated, so
`writeState` runs after and does not duplicate it — confirmed by test.
