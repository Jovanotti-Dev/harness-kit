# wsp-004 · Workspace-level migrate: fold a foreign root harness in, nothing deleted

- **Status:** ✅ done · closed 2026-07-27 · **Depends on:** `wsp-003`

## What was missing

`wsp-003` refuses `create` at a workspace root already carrying a foreign harness — correct,
but a dead end on its own. There was nowhere to go afterward except editing files by hand
outside any documented procedure. Single-repo `create` has exactly this repair path
(`--migrate`); workspace mode had no equivalent.

## Fix

Mirrors single-repo `--migrate` precisely — deliberately minimal, per the standing principle
"the script detects; you migrate" (`references/migrate.md`). `--migrate` does **not** classify
or move any old content. It only:

- bypasses the `wsp-003` refusal so the workspace skeleton generates;
- still prints the legacy report (which old files were found), so the human knows what to
  migrate;
- leaves existing files — most commonly `CLAUDE.md` — untouched, since `writeOut` already skips
  existing files unless `--force`;
- prints the same trailing `claudeConflict` warning single-repo does: the harness is
  unreachable until `CLAUDE.md` is rewritten by hand, and `audit` will report CRITICAL until
  then.

`tier`, `dryRun`, `force`, `addMember` were already threaded from `create.mjs` into
`generateWorkspace`; `migrate` now follows the same path.

## Docs

`references/workspace-migrate.md` gains a **Root migrate** section, clearly distinguished from
the existing hoist section (hoist promotes a harness found *inside a member*; root migrate
converts one already governing the root) — with its own mapping table (rules that are
genuinely shared go to the root `CONSTITUTION.md`; area-specific rules to
`constitutions/<area>.md`) and the same seven-step procedure as single-repo migrate, ending at
`archive/legacy/root/`.
