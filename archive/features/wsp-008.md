# wsp-008 · Workspace verify aggregate names the failing area(s)

- **Status:** ✅ done · closed 2026-07-27 · **Depends on:** —

## What was wrong

The root `verify.sh` orchestrator tracked `rc` (pass/fail) across all members but never
recorded *which* member(s) failed. The final line — `HARNESS_VERIFY: FAIL (workspace build)` —
gave no area name, so reading it meant scrolling back through every member's build/test output
to find the one that actually failed. Last row of the shakedown's original findings.

## Fix

`verify-root.sh.template` gains a `failed=()` array, appended to at every point `rc=1` is set
(both the single-area path and the run-all loop). The `FAIL` line lists them, comma-joined:

```
HARNESS_VERIFY: FAIL (workspace build — failed: web)
HARNESS_VERIFY: FAIL (workspace build — failed: api,web)
HARNESS_VERIFY: FAIL (workspace build :api — failed: api)
```

**One shell gotcha guarded against explicitly:** `${failed[*]}` is only ever expanded on the
`FAIL` branch, where `rc=1` guarantees the array is non-empty. Referencing an *empty* array
under `set -u` throws in bash 3.2 — macOS's default `/bin/bash` — even though the array was
declared; this template must run correctly there, not just under CI's newer bash.
